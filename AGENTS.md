# Night Stall: notes for agents

Read this before changing or adapting anything. `docs/guide.md` is the long version (written inside the sys0 repo,
where this app lived at `apps/night-stall/`: read that path as `app/`).

## The model in one paragraph

Every music source becomes a **score**: cues (`kick`, `snare`, `hat`, `bass`, `pad`, `lead`, `crash`… each with time,
velocity, duration, pitch and a lane) on a `Timeline` (`app/views/cues.ts`). Each animation frame asks the source what
song time will be **heard** when the frame reaches the screen (`player.heard(rafTime, 24 ms)`, mapped through the
audio clock), builds a `Moment` at that time (`stage/moment.ts`), and lets every **actor** answer it
(`stage/compose.ts`). Actors return poses for rig joints, lamp gains, water drive and light; the composer merges them;
`stall.set(pose, fx)` and `stall.draw(...)` render. Nothing reacts to raw audio levels directly; everything reacts to
cues, so it can wind up *before* a hit and land on it.

## Run and check

- `bun run dev` serves `standalone/` on port 4600 (`PORT=` to change). `standalone/play.ts` is about 70 lines: it is
  the minimal host and the best place to see the whole loop.
- WebGL in headless Chromium (Playwright) needs `--use-angle=metal --ignore-gpu-blocklist` on macOS
  (`--use-gl=angle` or a real GPU elsewhere); without a GPU the page loads but draws nothing.
- Timing goal: median and p95 frame interval 16.7 ms; a kick's first lit frame within ±8 ms of the kick.
  `window.__nsProfile = {}` makes `stall.draw` record per-stage GPU times (scene, mirror, data, finish) into it.

| File | Role | Adapting |
|---|---|---|

| `engine.ts`, `world.ts`, `world-0.ts` | generated by `app/art/build.ts`; never edit | rebake |
| `water.ts` | per-puddle damped wave equation driven by low hits and held bass | reuse |
| `stage/` | actor model (`actor.ts`), clip shapes (`clips.ts`), moment (`moment.ts`), composer (`compose.ts`) | reuse as is |
| `actors/*.ts` | one behaviour per thing: `hanging`, `rider`, `weather`, `lighting` are generic; `cat`, `sign`, `table`… specific | reuse, bind to new joints |
| `stage.ts` | the scene's actor list bound to rig joint names | rewrite per scene |
| `midi-file.ts`, `synth.ts`, `player.ts`, `song.ts` | MIDI reader/writer, GM Web Audio synth, lookahead player with `heard()`, demo song | reuse; write your own song |
| `cues.ts` | `Timeline`, roles, lanes, sections from a MIDI song | reuse |
| `analyze.ts`, `file-audio.ts` | offline analysis of an audio file into cues (onsets, kick/bass, tempo, beats, chords) | reuse |
| `live.ts`, `microphone.ts` | live listening: onsets from band levels, tempo votes, PLL phase, predicted beats | reuse `live.ts`; `microphone.ts` speaks the sys0 host's message protocol, so outside sys0 replace it with `getUserMedia` + an `AnalyserNode` |
| `band.ts` | the "animatronic band" panel: link each performer to a lane, the grid, another performer, or a tapped track | reuse in a full UI |
| `main.ts`, `main.html` | the full sys0 window | see "sys0" below |

## Adapting to a new scene

1. **Art** (`app/art/`): a component is `place => ({ id, sculpt(ctx), rig?(), lamps?(), light?(), glow?(), spot?(), warms?(), emitters?() })`.
   Tag each joint's splats `<id>.<joint>`; `rig()` names joints with pivots (and `swing` for hanging things); `lamps()`
   declares live lights. `scene.cjs` lists components in sculpt order (random draws follow that order).
2. **Bake**: `bun run bake /path/to/shapeshift-labs-ink-studio` (clone Ink Studio at revision
   `a7e8eacb2795c39cbc29cce5ff1e805ebeb13d52` and `npm install` it). It rewrites `engine.ts` and `world*.ts` (~30 s).
3. **Behaviour**: write `stage.ts` for the new rig, reusing actors:
   `hanging(rig)`, `rider("cafe.table.cup", "cafe.table.hop", { rot: [4, 0, 0] })`, `cat("cat2")`, `sign("bar.sign", "bar.sign.glyph")`.
   A new actor is `actor({ id, amount, plays, idle, actions, reactions })`; see `docs/guide.md` §3.
4. **Mapping first**: before code, write the mapping table (element, rank, the one cue it listens to, motion, decay in
   beats) as `docs/playbook.md` §3.1 describes. Music changes how things move and shine, never what they are.
5. **Show amounts**: `show` (0–1 per element) scales each actor; `lighting` tunes the live lamp model.

## Rendering budget

Cost is mostly per splat (vertex), not per pixel: Fine pixels (1280×720 art pixels) cost about what Classic
(640×360) does. The mirror and lighting data passes draw at half the art resolution and the finish shader upsamples;
the data pass redraws on camera moves and otherwise every third frame. `draw(time, view, light, w, h, "fine" | "classic", scale)`
takes a dynamic-resolution `scale` (0.6–1); `app/views/main.ts` shows the controller (steps of 0.1 with hysteresis).

## sys0 (only if hosting inside sys0)

`app/` is a sys0 native app: `app.json` declares saved state, `band.json` its methods, `src/main.ts` the actions
(`setShow`, `setSync`, `setLighting`, `setLink`, `saveTrack`…), and `views/main.ts` exports `mount(ctx)` where `ctx`
gives `el`, `props(path)`, `act(method, input)` and optionally `audioLevels`. `src/app.ts` is generated from `app.json`,
and `src/main.test.ts` imports sys0's test helper, so neither runs on its own. Outside sys0, write a host like
`standalone/play.ts`: keep the state in an object and call the renderer and stage directly.

## Traps

- `engine.ts` is generated minified JavaScript; import it as `* as engine` and cast to `any`.
- Ink Studio offers itself to `require` behind `typeof` checks: the bake rewrites `require(` to a stub so bundlers don't chase it.
- Probes must use the same `ahead` (24 ms) the view uses, or frame errors are off by the difference.
- Overlapping water impulses sum into blobs: keep hits zero-mean (see `water.ts`).
- More in `docs/guide.md` §7.
